## 🔴 Ce qui ne marche pas

### Attractions publiées quasi vides : 2 476 publiées, mais 0 fady, 0 « meilleurs mois », 6 tarifs
Preuve (SQL `count(*)` sur `attractions`, 16/08) : total 2 521, publiées 2 476, avec photo 226 (9,1 %), avec description 157 (6,3 %), avec résumé 219, avec tarif (résident ou non-résident) 6, avec fady 0, avec best_months 0.
Conséquence : toute fiche attraction qui promet tarifs/fady/période affichera du vide dans ~99 % des cas ; 9 fiches sur 10 s'ouvrent sans photo.

### Établissements : 3 254 pages publiées, ZÉRO photo, zéro horaire, zéro propriétaire
Preuve (SQL sur `pages`) : total 3 355, publiées 3 254 ; avec visuel (cover OU logo OU galerie) **0** — contre-vérifié : `cover_url` non nul = 0, `logo_url` non nul = 0, `gallery` non vide = 0 ; `owner_id` distincts = 0 ; `page_hours` liées = 0 ; avec téléphone 379 (11,6 %), avec prix (`price_min_ar`) 38 (1,2 %), avec description courte 89 (2,7 %).
Conséquence : l'annuaire des hébergements/restaurants est une liste de noms gris — aucune vitrine visuelle, presque aucun moyen de contact ni de prix ; aucune page n'est revendiquée par un professionnel.

### Événements : 42 publiés, 0 date réelle, 0 affiche, 0 rattachement à un lieu du référentiel
Preuve (SQL sur `events`) : 42 publiés ; `starts_on` non nul = 0 (donc « à venir » = 0) ; `poster_url` = 0 ; `place_id` = 0 ; `page_id` = 0 ; tous n'ont qu'un `lieu_libre` texte (0 ligne sans aucun lieu).
Conséquence : impossible d'afficher « quand » précisément ni de guider vers l'événement ; aucun événement n'est cliquable vers une destination ou un établissement.
Nuance : les 42 ont tous `periode` + `mois` renseignés (30 « periode_sure », 9 « certaine », 3 « incertaine ») — l'affichage par mois reste possible, l'affichage par date non.

### Le « réseau social » compte 1 auteur : 28 récits publiés, tous de la même personne
Preuve (SQL sur `posts`) : 28 récits, tous `status='published'`, **1 seul `author_id` distinct**, 28/28 avec lieu et médias.
Conséquence : le fil ressemble à un blog personnel, pas à un réseau social ; aucun contenu communautaire à montrer au lancement.

### Plats : 95 fiches, 0 photo, 0 liaison vers une carte de restaurant
Preuve (SQL sur `dishes` + `menu_items`) : 95 plats, `photo_url` renseignée = 0, liés à au moins un `menu_items` = 0, `nb_restaurants>0` = 0 ; points positifs : 95/95 ont une description, 72/95 une fourchette de prix.
Conséquence : /gouts ne peut montrer ni photo ni « où le manger » — la promesse centrale d'une page gastronomie.
